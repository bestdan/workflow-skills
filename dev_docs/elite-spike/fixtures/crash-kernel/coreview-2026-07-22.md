# Probe 5 draft — co-review (codex + Fable), 2026-07-22

Independent reviews of **v1** of `draft-state-machine.md` + `probe5-crash-kernel.md`,
requested before building the fixture. Both reviewers **independently falsified
the v1 draft on paper** (allowed executions violate the stated invariants before
any fault is injected) and both agreed the **flat-file protocol is salvageable —
SQLite is not yet warranted**, because the worst holes are spec/liveness/authority
bugs that survive a storage swap. v2 (this commit) encodes the fixes.

Reviewers: **codex** (gpt, high reasoning — read the macOS `fsync`/`rename`/
`flock`/`lockf`/`fcntl` man pages directly) and **Fable** (claude-fable-5).

## Pass-bar critique (both)

- Passing A–J ≠ "every outcome" — A–J omits the critical schedules.
- A protocol-**emitted** dup/gap must **fail** the probe; "alert, not repair" is a corruption-detection requirement, not permission to pass after emitting an invalid sequence.
- The falsifier wrongly conflates "an invariant failed" (→ falsifies *this* draft) with "flat-files can't be tightened" (→ determines the *redirect*). Decouple them.
- Best achievable positive result is **"not falsified in the tested (process-crash) environment,"** not "proven"; reboot/power-loss durability is **inconclusive** unless a real power-fail harness (VM/loopback) is built.

## Decision on the crashed-active orphan (finding #1) — CONSENSUS: option (b)

Both independently recommend **(b): the watcher never signals processes itself but
triggers a generation-scoped `ap-stop` (`--reap`)** — one audited kill path, not a
second authority. **(c) rejected** (a live orphan can still mutate repos/external
systems → not a safe hold). §5.1 reword: *the watcher never signals processes
itself, but may trigger a generation-scoped stop on kernel-defined conditions.*

**Decisive safety argument (both): orphan-hood is proven by the lock, not by
observation.** The launcher holds the repo lock continuously from `prepared`
through release, so `ap-stop --reap` **winning `lockf -t 0` is the linearization
point** proving no live launcher exists — and holding it through
terminate→`observed_terminal`→release fences any successor (takeover publishes
g+1 under the same lock). Owner mismatch or lock contention → **signal nothing**.

Guards the kernel must encode (union):
- Target only by **incarnation identity** (`p_uniqueid` + start-time + exe +
  boot-session), never an agent-authored PID; never `killpg` a stored pgid.
- **Kill-TOCTOU (codex):** `proc_pidinfo`-check-then-`kill(pid)` still races PID
  reuse between check and signal. Without a **non-escapable containment boundary**
  (the run's own process group established before `active`, so no unregistered
  descendant survives) that gap is **itself a Probe 5 falsifier** → first-class
  matrix row.
- Re-validate immediately before signaling; prove containment + every recorded
  incarnation dead **before** `observed_terminal`.
- **Durable stop-intent + idempotent retry** on a later pass if termination is
  incomplete; the generation stays admission-fenced meanwhile.
- **Alive-but-hung launcher (Fable):** still holds the lock → `--reap` refuses →
  human **alert**. That is a *hang*, not a crash outcome, so it stays
  Decision #5-compatible — state it explicitly.

## Second pass — codex on v2 (verdict: still falsified on paper)

A follow-up codex review of **v2** found that v2 did not close the top hole and
that merging the two reviewers' v1 fixes introduced a contradiction. v3 (next
commit) addresses these.

**Decisive defect — auto-reap contradicts the lock-lifetime fix.** Fable's
orphan-proof assumed the launcher holds the repo lock *for its whole life*; but
v2 also adopted codex's transaction-lock/lease-record split, which made the lock
**short-lived per-transition**. During normal `active` the lock is therefore
**free**, so `ap-stop --reap` winning it proves nothing about launcher liveness →
**it could kill a healthy running task** (and FD inheritance gives the opposite
false reading). Fix: **two locks** — a **run-long liveness lock** (`CLOEXEC`,
held the entire run, sole purpose = liveness proof; winning it non-blocking =
launcher dead) separate from the **short-lived transaction lock** (serializes
transitions).

Other v2 holes (all addressed in v3):
- **Start gate has two unrecoverable windows** — crash after spawn/before
  `active` (owner `prepared`, maybe no incarnation; reap only accepts `active`);
  crash after `active`/before opening the gate (recorded process alive, stale
  predicate never fires). Child blocked forever or proceeds unrecorded.
- **pgroup only *narrows* R4, not a fence** — descendants can `setpgid`/`setsid`
  out; PGID non-reuse is guaranteed only during the group's lifetime. Needs an
  anchored group/session identity + escape detection.
- **Generation reservation not durably recorded at launch** — `g` lives only in
  the owner; X5 has no source of truth. Add a durable generation-reservation
  registry record (+ a global seq-head as the seq source of truth).
- **Recovery state underspecified** — `stop-intent` not in the schema/enum;
  `observed_terminal` not idempotent; X4 asserts convergence without a defined
  recovery transition. Add an explicit recovery table.
- **No two-lock ordering contract** — specify total order liveness → transaction
  → registry; forbid inversion.
- **Registry rewrite doesn't scale** (O(history) read, O(month²) write) and a
  non-blocking append can silently drop one intended write. Move to O_APPEND +
  fail-closed reader + a durable seq-head HWM.
- **Matrix still bundles multiple schedules per row** (E, X1–X4) — split to one
  deterministic crash point per row; add false-reap-of-healthy-active, gate-window,
  group-escape, lock-inversion, and gen-loss-before-registry rows.
- Nits: "protocol is *correct* for power-loss" → "designed for"; the `confirmed`
  label conflicts with the "not falsified" ceiling.

**Confirmed sound in v2:** acquire-clobber fix (I), stable lock inode,
`observed_terminal`-after-verification, `claimed_exit` (K), global-seq structural
serialization, incarnation identity for *observation*, generation fencing for
specified mutations. The epistemic bar (process-crash only, reboot inconclusive,
"not falsified") is sound; the acceptance bar is not until the matrix exercises
the reap/gate/R4/X5 premises.

## Third pass — Fable on v3 (verdict: not yet buildable; 7-item fix set)

The three-lock model closed the v2 contradiction *structurally*, but Fable found
**3 new on-paper CRITs + 4 HIGHs** — two CRITs being crash-then-continue
schedules the v3 matrix would not even detect (so the fixture would pass a broken
protocol). v4 (next commit) applies the fix set.

- **CRIT-1 — torn trailing → torn interior line.** Crash mid-append (S2) leaves a
  partial last line; the next O_APPEND writes after it → the torn line is now
  interior → reader fails closed forever, and the *protocol emitted it*.
- **CRIT-2 — S4 retry emits a duplicate seq.** Append commits, seq.head publish
  crashes → line ignored → retry derives seq from the stale head → same seq → two
  committed lines with seq=N → falsifies invariant 8.
  → CRIT-1/2 share one fix: a **tail-reconciliation step** under the registry
  lock (validate tail; ftruncate a torn partial; adopt-or-truncate any seq>head
  line) before deriving the next seq. Add S2→append and S4→append rows.
- **CRIT-3 — prepared recovery wedges the repo.** The recovery table never moves
  the owner out of `prepared`; LAUNCH requires `{absent, terminal}`, so every
  future launch refuses forever → permanent human-needed wedge. Fix: terminalize
  the owner in the prepared row; amend C1–C3 to "next launch proceeds."
- **HIGH-4 — liveness lock primitive unspecified; invariant 9 overclaimed.** The
  drawn LAUNCH forks (no exec) so the CLOEXEC-on-exec catastrophe is avoided, but
  flock is fork-shared regardless of CLOEXEC, and the draft never says the
  liveness holder must be a **run-long supervisor**. Fix: use **fcntl/POSIX
  `F_SETLK`** (not fork-inherited, so a worker can't fake liveness; single-fd
  discipline), state the supervisor lifetime, demote invariant 9 to the X3
  hypothesis, and state the fail-safe semantic (killing the supervisor reaps a
  healthy run).
- **HIGH-5 — Br vs S4 contradict on `generation_reserved` commit semantics.**
  Fix: g-derivation reads *uncommitted* reserved lines (safe — no owner was
  published); bound the scan; add the between-append-and-head-publish row.
- **HIGH-6 — takeover publishes g+1 over live gen-g workers** (v1 live-orphan
  hazard via the side door). Fix: takeover runs the reap recovery table for gen g
  first, then publishes g+1 and becomes the new liveness holder.
- **HIGH-7 — "signal the session" is not a primitive; gen_token-scanned
  unrecorded processes have an unfenced kill-TOCTOU.** Fix: pgroup enumeration +
  `kill(-pgid)` + re-scan-until-clean; token path signals by `-pgid` (after sid
  re-check), not `kill(pid)`; add the token-scan reuse row.
- MED/LOW: R3's testable outcome = "reap refuses, reason=liveness-held" (the
  alert is the watcher's job, depends on Probe 3); `launch_aborted` idempotency +
  "no-op = appended-but-inert"; `stop_intent` cleared by the completing pass;
  R4b escape-detection mechanism (`proc_listpids` over uid + `KERN_PROCARGS2` for
  gen_token with sid ≠ run session); kill-sheet said "v2 matrix / ten invariants"
  (v3 has eleven).

**Closed cleanly in v3:** two-lock-ordering contract, matrix de-bundling, the
`stop_intent`/recovery-table shape, and the `confirmed`-ceiling wording. Fable:
v3 is *architecturally right* — no redesign or storage swap needed; SQLite would
subsume CRIT-1/2 but not 3–7.

## Fourth pass — codex on v4 (verdict: still not buildable → v5, or take the redirect)

CRIT-3 (prepared wedge) **closed**. But the two registry CRITs are only
**partially** closed and the liveness primitive is **nominal, not closed**:

- **CRIT (registry seq) persists.** "Adopt any valid `seq > head`" is too weak:
  it blesses a *gap* (adopt N+2 with head=N) instead of failing closed, doesn't
  define "the tail" across month files (crash before head-publish + month
  rollover ⇒ N+1 re-emitted), and doesn't require newline-terminated completeness
  or a synced truncation. Fix: exact **`seq == head+1`**, newline-terminated,
  `F_FULLFSYNC` the truncation, cross-month aware, fail-closed on gaps/multiples,
  and store more in `seq.head` (seq + month/file + end offset or record hash).
- **CRIT (fcntl close-trap) persists.** POSIX `F_SETLK` drops **all** the
  process's locks on the **first close of any fd to that inode** — so a
  status-reader/alias/library that read-opens+closes the lock path silently drops
  liveness → false-orphan reap of a healthy run. Discipline is not a guarantee;
  X3's "no early-close drop" is *impossible* for POSIX locks (documented macOS
  behavior). codex also corrected v4's stale premise: `F_OFD_SETLK` **is** exposed
  on this SDK (fork-shared, so not a drop-in either).
- **CRIT (takeover handoff undefined).** A takeover process can't atomically hand
  a process-owned POSIX lock to a *forked* supervisor (release-then-acquire =
  competitor window; acquire-before-release = fails). Must **exec** into the new
  supervisor preserving the fd, or a fenced gated handshake.
- **HIGH — termination not proven convergent** (no TERM→KILL escalation/bounds;
  re-scan-until-clean doesn't converge under fork churn) and **`kill(-pgid)` has a
  PGID-reuse-at-signal window** (distinct from PID reuse) that conflicts with the
  absolute no-mistarget pass bar.
- **HIGH — matrix still incomplete** (crash-during-truncate/adopt, S4+rollover,
  multiple/gapped `seq>head`, same-inode read-open-close→false-reap, handoff
  race, PGID reuse, fork churn).

**Meta-signal:** across four passes the **registry/seq layer keeps failing in the
same class** (exact-once ordered sequence under crash), which is precisely the
redirect the kill sheet names — a transactional store (SQLite/WAL) subsumes it.
The liveness-lock/orphan-reap flat-file design is closer but needs a deliberate
lock-topology decision (there is no clean macOS primitive: flock/OFD are
fork-shared, fcntl has the close-trap + no fork-handoff).
