# co-review reviewer — `devin` (Cognition Devin CLI)

`devin` is a built-in default reviewer. Like `agy` — and unlike stateless `codex` — it is **cloud-backed and session-based**: it authenticates to Devin's cloud, runs the model there, and persists a **session per directory** (`devin list`, `-c/--continue`, `-r/--resume`). It therefore **requires a Devin login, network access, and a plan with access to the pinned model** — its invocation **cannot run inside a restrictive Bash sandbox** (under sandbox it panics trying to write its own log file). If `devin` errors with `/upgrade to access this model`, `not authenticated`/`unauthorized`, `session/set_mode failed: … restricted by your organization's policy`, or a network/permission failure, treat it like any missing reviewer: note it, skip it, never fatal. Its voice is Cognition's own SWE model, distinct from Claude, OpenAI (`codex`), and Gemini (`agy`).

Read the shared dispatch contract in [`../SKILL.md`](../SKILL.md) — single-shell-call, the `<INPUT>` / `<REQUESTS>` / `<POINTER>` placeholders, per-agent paths, and the shared **probe warnings** (never wrap a probe in `timeout`; disambiguate `127`) — before using the probe and invocation below.

## Pre-flight probe

Auth is file-based, so it has **no keychain/SSH split like `agy`** — credentials live in `~/.local/share/devin/credentials.toml` and work identically over SSH. But still **pre-flight probe before dispatching**: run bare `devin auth status` (no `timeout` wrapper — see the shared probe warnings in SKILL.md) — **rc 0** in <1s when logged in and prints the tier plus **allowed models** (so it doubles as a model-gating check); **rc≠0** / `not authenticated` when not. If it fails, **skip `devin`** (note it, never fatal) instead of dispatching.

## Driving quirks (verified against `devin 3000.3.22`, except where a bullet names its own version)

Because it's stateful and agentic, drive it as a reviewer this specific way:

- **Feed the prompt via `--prompt-file`, never stdin.** This is not the codex/agy stdin pattern. Bare `devin -p` reading piped stdin **panics** (`repl_mode` unwrap on `None`); an inline `devin -p "<prompt>"` argument **suppresses stdin entirely** and makes devin ignore your diff and instead auto-load ambient repo context (git status, `AGENTS.md`, etc.). The only reliable path is to write the assembled `rubric + requests + diff` to `<INPUT>` and pass `--prompt-file "<INPUT>"`. `<INPUT>` is a **fixed absolute path** so the command stays invariant — but note it now appears **in the command string**, so devin's exact-match allow-rule includes that literal path (unlike codex/agy/copilot, which pipe via `cat` and keep the path out of the command).
- **Validate `<INPUT>` is non-empty first** (`[ -s "<INPUT>" ] && devin …`), exactly as for `agy`: never hand a stateful agent an empty prompt file.
- **Always start a fresh session.** Never pass `-c`/`--continue` or `-r`/`--resume` for a review — each review must depend only on the current diff, never on an accumulated session.
- **Read-only is enforced structurally, not by prose.** Pass **`--permission-mode auto`** (auto-approves _only_ read-only tools; in non-interactive mode any edit/command that isn't auto-approved is denied, not queued). **Never** pass `accept-edits`, `smart`, or `dangerous`. Keep the flag in the command **and** its allow-rule — don't rely on the rubric alone. devin is agentic and will otherwise explore the repo, so the rubric's "review only what follows" framing matters.
- **Do _not_ pass `--sandbox` — it is currently unusable, and this is a known downgrade.** It used to be the second structural guard here (devin's own OS-level read/write scope enforcement — macOS seatbelt / Linux bwrap+seccomp, distinct from the Bash-tool sandbox; the `devin` process itself must still run **unsandboxed** at that level, since it needs network + log writes). As of `devin 3000.3.22` the flag makes devin request ACP session mode `autonomous` during `session/new`, and any account whose org gates that mode fails the handshake before the model is ever reached:

  ```
  Error: session/set_mode failed: Invalid params:
    "Mode 'autonomous' is restricted by your organization's policy"
  ```

  Bisected: `--sandbox` **alone** is sufficient to trigger it; `--prompt-file`, `--model`, and `--permission-mode auto` are all clean individually and together. So the fix is to drop only `--sandbox`. **Be honest about the cost:** read-only enforcement now rests on the tool layer (`--permission-mode auto`) alone, with no OS-level backstop, on a reviewer that is fed your full diff. Note the failure is **account-specific but the drop is global**: the built-in invocation carries no `--sandbox` for anyone, because the command must stay invariant for the approve-once exact-match rule (a try-with-then-retry-without path would need two command strings and two allow-rules — see [`../references/permissions.md`](../references/permissions.md)). So if your org does **not** gate `autonomous` mode, you lose nothing by adding `--sandbox` back to both the invocation and its allow-rule yourself — and do the same if a future devin release stops requesting `autonomous`, or your org lifts the restriction.
- **Pass `--respect-workspace-trust false` — non-interactive mode cannot answer the trust prompt.** devin refuses to run in a workspace it has not been trusted in (`Error: Refusing to run in an untrusted workspace: <path>`), and `-p` mode has no way to show the prompt, so the review dies before the model is ever reached. Trust is granted interactively per directory and stored as a **prefix** match in `~/.local/share/devin/cli/trusted_workspaces.json`, so a `git worktree` created under an already-trusted parent inherits trust — but one created outside it does not, and neither does a `--post` review of a repo cloned elsewhere. The flag waives the check for that one invocation only. **Be honest about what the waiver costs: it is narrower than the config key, not safer in kind.** Whichever way you skip the check, the reviewed workspace's own agent config reaches the model — devin discovers always-on rules from `.windsurf/rules/*.md`, conditional ones from `.cursor/rules/*.md`, and project skills from `.devin/skills/<name>/SKILL.md`, all relative to the cwd. Verified: with the flag passed in an untrusted directory, a repo-controlled `.windsurf/rules/probe.md` carrying `trigger: always_on` steered the reply. So prefer the flag over `skip_workspace_trust: true` in `~/.config/devin/config.json` for its **duration** — the config key drops the guard for _every_ future invocation, interactive ones included, while the flag drops it for this dispatch alone — and not because it keeps the repo's content out. It does not. On a dispatch that already runs without the Bash sandbox and without devin's own `--sandbox` (see the bullet above), that leaves contributor-controlled prompt text able to steer the reviewer, which bites hardest in `--post` mode, where the checkout belongs to someone else. The invocation below closes that vector rather than only documenting it: it runs devin from a fixed, empty `<NEUTRAL>` directory, so no repo-local `.windsurf/`, `.cursor/`, or `.devin/` is on the cwd path to discover. Beware devin's own error message, which tells you to set `respect_workspace_trust: false` in the config — that key is not in the config schema and is silently ignored (verified against `devin 3000.6.2`). The config field is `skip_workspace_trust`; only the CLI flag is spelled `--respect-workspace-trust`.
- **Keep `--model` last.** Every flag added here goes _before_ it, as `--respect-workspace-trust false` does. The order is a convention shared with `agy` and the `orchestrate-coders` mirror, set deliberately in #347 so the volatile flag sits at the tail; the wildcard that originally motivated it was dropped in the same PR, so the order now buys consistency rather than safety — but this file, [`agy.md`](agy.md), and the `orchestrate-coders` mirror in [`cli-coders.md`](../../orchestrate-coders/backends/cli-coders.md) all follow it, and a reviewer whose command drifts from its rule goes missing silently (see the upgrade note below).
- **Pin `--model`; default `swe-1.6`.** The built-in invocation defaults to **`swe-1.6`** — free on Pro; in testing it flagged an injected bug correctly in ~3.5s. **Never rely on the unpinned default or the bare `swe` alias:** as of 2026-07 `swe` resolves to **`swe-1.7-lightning`, which is billed** ($2.50/$12.50 per Mtok), so an unpinned "cheap" reviewer silently becomes a paid one. `swe-1.7` (free on Pro, 262K ctx) is the newer sibling but is **beta** and publishes no absolute benchmark standing, which is why the pin stays at `swe-1.6`.
- **Devin is now a model marketplace, and that changes what pinning means.** `devin models list` reports **37 families** spanning Anthropic, OpenAI, Google, xAI, Moonshot, Zhipu, DeepSeek, NVIDIA, and Thinking Machines. So `model:` picks a **vendor and jurisdiction**, not just a capability tier — and Cognition's [privacy policy](https://cognition.com/privacy-policy) names no model provider for any of them. Since a reviewer is fed your **full diff**, pin deliberately: prefer a Cognition-native `swe-*` model, and don't reach for `glm-*`/`kimi-*`/`deepseek-*` on proprietary code. Vendor-diversity reviews are better served by the `agy` or `codex` reviewers, whose serving path is documented. Routing `claude-*`/`gpt-*` through devin is pointless here — it adds an undocumented hop in front of a vendor co-review can already call directly.
- **Tier gating exists but is no longer the old shape.** Access is still tier-gated (a locked model returns `/upgrade to access this model`), but the previously documented Free-tier pin `swe-1.6-slow` **no longer appears in the model list at all**; verify what your tier actually offers with `devin models list` rather than trusting a hardcoded fallback. Pin via the config object form `- {name: devin, model: <m>}`. Note a stale-auth trap: right after upgrading, cached auth still reports the old gating, so a just-unlocked model can spuriously return `/upgrade` on the first call — re-run `devin auth status` (which re-fetches) and retry before concluding a model is unavailable. Changing the model changes the command string and re-prompts the exact-match approval.
- **Treat `devin` as advisory-only, always reconciled** — like every external reviewer, its output must pass through the reconciler; never let it be the sole reviewer.

**Upgrading from any earlier release?** devin's dispatch string has changed more than once — the neutral cwd and `--respect-workspace-trust false` arrived in v2.13.1, the flag order moved after it — and it will change again. An allow-rule written against an older string does not match, and it does not announce itself. So do not reason about which release you came from: **diff all four of your rules byte-for-byte against [Permission allow-rules](#permission-allow-rules-exact-match-approve-once) below and replace any that differ.** Miss one and devin re-prompts on every interactive run, and drops out **silently** under `--non-interactive`, where an unapproved command is denied rather than queued — the reviewer simply stops appearing in the run summary.

## Invocation (assemble + dispatch in one shell call)

- **GitHub mode, with requests** → `cat "<this skill dir>/review_prompt.md" "<REQUESTS>" > "<INPUT>"; gh pr diff <n> --repo <owner>/<name> >> "<INPUT>"; [ -s "<INPUT>" ] && mkdir -p "<NEUTRAL>" && cd "<NEUTRAL>" && devin -p --prompt-file "<INPUT>" --permission-mode auto --respect-workspace-trust false --model "swe-1.6"` — devin reads the assembled `rubric + requests + diff` from the file via **`--prompt-file`** (there is **no stdin pipe** and **no `-p "<POINTER>"` argument** — piping stdin panics and an inline prompt suppresses the file; the rubric itself carries the read-only instruction). The leading `[ -s "<INPUT>" ] &&` is the same empty-input guard used for `agy`. `--permission-mode auto` enforces read-only at the tool layer (`--sandbox` is deliberately absent — see the driving quirk above); `--model "swe-1.6"` is the default pin (swap via the config object form, which needs its own new exact-match allow-rule below — check `devin models list` for what your tier allows, and read the marketplace caveat above before picking a non-`swe-*` model). `mkdir -p "<NEUTRAL>" && cd "<NEUTRAL>"` runs the reviewer from a **fixed, empty, user-level directory** instead of the repo, because devin's rule and skill discovery is cwd-relative — see the trust bullet above for the injection this blocks. Order matters: the `gh pr diff` (or `git diff`) runs first, while the cwd is still the repo — `--repo <owner>/<name>` (the repo resolved in SKILL.md step 2, never `cwd`'s by default) makes this independent of that cwd too. `<NEUTRAL>` must be **dedicated and empty** — never the repo, `$HOME`, or the `<INPUT>` directory, which holds other reviewers' assembled diffs. The `mkdir -p` is what keeps the `cd` from failing on a fresh machine and silently skipping the reviewer; both are fixed paths, so the command stays invariant. devin needs network + a Devin login, so this line must run **unsandboxed** in the Bash tool. **Never** add `-c`/`--continue`/`-r`/`--resume` — every review is a fresh session.
- **GitHub mode, no requests** → drop the `"<REQUESTS>"` argument: `cat "<this skill dir>/review_prompt.md" > "<INPUT>"; gh pr diff <n> --repo <owner>/<name> >> "<INPUT>"; [ -s "<INPUT>" ] && mkdir -p "<NEUTRAL>" && cd "<NEUTRAL>" && devin -p --prompt-file "<INPUT>" --permission-mode auto --respect-workspace-trust false --model "swe-1.6"`
- **`--local` mode** → swap the `gh pr diff …` segment for `git diff <base>` and append any untracked files you read, per the shared `--local` rule in SKILL.md. Keep the `--prompt-file "<INPUT>"` tail (there is no `cat "<INPUT>" |` pipe for devin).

## Permission allow-rules (exact-match, approve once)

Merge into the `permissions.allow` array (see [`../references/permissions.md`](../references/permissions.md)). The first two prepare and enter the neutral cwd, the third is the reviewer command, and the fourth is the pre-flight auth probe. Replace `<NEUTRAL>` with the same literal fixed absolute path the invocation uses, and `<INPUT>` in the rule with the **same literal fixed absolute path** the invocation writes to (it appears in the command because devin reads it via `--prompt-file`); keep it a stable user-level path so one rule works across repos:

```json
"Bash(mkdir -p \"<NEUTRAL>\")",
"Bash(cd \"<NEUTRAL>\")",
"Bash(devin -p --prompt-file \"<INPUT>\" --permission-mode auto --respect-workspace-trust false --model \"swe-1.6\")",
"Bash(devin auth status)"
```

The `--prompt-file "<INPUT>"` path plus the full flag set, including the exact pinned `--model` value, must match **byte-for-byte** between the command and the rule. **Do not wildcard at any flag** (`--model:*`, `--respect-workspace-trust:*`, or any earlier one): Claude Code's Bash permission patterns match any suffix following the fixed prefix, not just the next token, so the wildcard approves everything after that prefix — e.g. `--continue`, breaking the fresh-session rule above, or an unsafe permission mode, defeating the read-only guarantee `--permission-mode auto` is supposed to provide. Wildcarding a flag that is _not_ last is the worse case, not the safer one: `--respect-workspace-trust:*` swallows the `--model` pin as well, so moving `--model` to the tail makes that wildcard less tempting without making it safe. If you pin a different `devin --model` or a different read-only flag, add a new exact-match rule for it instead.

> `devin auth status` is the same per-coder probe the `select-coder` skill's [`scripts/probe-coders.sh`](../../../scripts/probe-coders.sh) runs for its availability cache. co-review keeps its own **live** rc-gate rather than reading that (possibly 30-day-stale) cache. If you change the probe command, update it in both places so they don't drift.
